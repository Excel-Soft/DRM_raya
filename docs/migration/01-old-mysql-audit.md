## 5. AUTO_INCREMENT

Auto-increment is applied via trailing `ALTER TABLE ... MODIFY ... AUTO_INCREMENT` (163+ such clauses). Sequence values are embedded (e.g. `AUTO_INCREMENT=1652` on some tables). PostgreSQL migration must map these to **`GENERATED BY DEFAULT AS IDENTITY`** or sequences and preserve IDs where the modern schema uses integer PKs.

## 6. MySQL-specific syntax (will not run on PostgreSQL)

- `` `backtick` `` identifiers
- `ENGINE=InnoDB`, `DEFAULT CHARSET`, `COLLATE`
- `AUTO_INCREMENT` and `MODIFY` auto-increment resets
- `enum(...)` and MariaDB `tinyint(1)` booleans
- `DEFAULT current_timestamp()` and **`ON UPDATE current_timestamp()`** (**15** column definitions)
- `int(11) UNSIGNED`, `bigint(20) UNSIGNED`
- MariaDB conditional comments `/*!40101 ... */`
- Zero-date sentinel **`0000-00-00`** appears in dump metadata and legacy data patterns (invalid in PostgreSQL `date`/`timestamp` without transformation)
- phpMyAdmin transaction/session pragmas

**Do not** pipe this file into `psql`.

## 7. Legacy naming patterns

- **`webxl_*`**: primary application tables (~150+)
- **`tbl_*`**: older parallel invoice/customer tables (`tbl_customers`, `tbl_invoices`, `tbl_invitems`, `tbl_receipts`) — potential **duplicate domain** vs `webxl_company` / `webxl_invoice`
- **`activity_logs`** vs **`webxl_activity_logs`**: duplicate logging shapes
- **`password_resets`** vs **`webxl_password_reset_emails`**

## 8. Migration risks (source-side)

1. **Volume:** ~901 MiB SQL, multi-million-line file — requires streaming ETL, not in-memory load.
2. **Weak FK enforcement:** Orphan `com_id`, `user_id`, and task link references likely exist.
3. **Parallel schemas:** `tbl_*` vs `webxl_*` may duplicate customers/invoices; cutover rules needed.
4. **Zero dates and nullable timestamps:** Must be normalized before PostgreSQL insert.
5. **ENUM / status vocabularies** differ from modern Drizzle enums (different casing and values).
6. **PII / secrets in data:** User rows, passwords, tokens, customer contact fields — reports must not sample row contents (this audit did not extract row payloads except structural INSERT counts).
7. **Large text fields:** Product/service descriptions may include HTML in `LONGTEXT` columns (observed in dump stream); treat as opaque text during audit.
